# 域名监控

在管理后台打开「域名监控」，添加需要监控的注册域名。可以先点「查询当前 NS」，再到注册商后台核对预期 NS。保存的预期值不会随着线上解析自动更新。普通域名可以只配置 NS 和注册状态检查；有隧道或其他关键业务时，建议额外添加记录检查。

例如：

| 配置 | 示例 |
| --- | --- |
| 注册域名 | cpolar.top |
| 预期 NS | vip1.alidns.com、vip2.alidns.com |
| 记录名称 | *.cpolar.top |
| 记录类型 | CNAME |
| 预期值 | cpolard.cpolar.top |

记录检查支持 A、AAAA、CNAME。泛解析规则每次检查使用新的随机子域名。权威 DNS 和公共 DNS 分别检查，公共 DNS 也会验证 CNAME 链能解析到 IP。A 和 AAAA 按完整预期地址集合比较，使用按地区或轮询返回部分地址的域名应选择具有稳定值的监控记录。

- 「系统设置 → 基本设置 → 域名监控」可以调整 DNS 检查间隔、注册局 RDAP 检查间隔、异常连续确认次数和到期提醒节点。默认 DNS 每分钟、RDAP 每五分钟、连续两次确认，到期提醒为 60、30、15、7、1 天及已到期。
- 父区 NS 至少有一台返回与预期一致、且其他有效回答没有冲突，即视为一致；个别超时只保留在明细。所有探测都没有有效回答时，单独记探测异常，不判定域名没有委派。两台父区服务器同时返回委派异常时直接告警；其他 DNS 异常按设置的确认次数确认。注册局状态、冻结、赎回或删除状态单独检查。
- 可在域名配置中选填到期日。续费提醒优先使用手填日期，清空后恢复使用注册局日期。注册状态继续单独查询。
- DNS 探测超时或结果不完整仍按设置确认。注册查询超时、限流或没有公开 RDAP 时，跳过本次注册结果，不计入异常或发送告警。注册局已确认的异常不会因查询失败而消失；已知或手填的到期提醒保持原有行为。
- 故障、恢复与到期提醒统一进入「告警记录」，可以按主机或域名筛选。「系统设置 → 基本设置 → 域名通知」使用独立的钉钉机器人和加签密钥，不会回退到主机通知群，也不会在后来配置机器人时补发此前标记为无通知渠道的旧事件。每个域名可关闭钉钉通知，也可单独设置持续故障的提醒间隔。请求失败后由调度器重试。

## 阿里云短信（可选）

域名告警可以通过阿里云短信服务（SendSms，V3 签名）发到指定手机号，与钉钉开关相互独立。

### 准备

1. 在阿里云短信服务控制台申请**签名**和**通知短信模板**，审核通过后记下签名名称和模板 Code（如 `SMS_123456789`）。模板需包含 `${name}`、`${time}`、`${status}`、`${msg}` 四个变量，例如：

   > 服务器故障通知：服务器${name}于${time}时间有故障，状态${status}，告警信息：${msg}，请您及时联系技术人员处理。

   申请时变量属性：`${time}` 选「时间」，其余选「其他」，并在场景说明里写明 `${name}` 传入的是被监控的域名，附一条完整示例。阿里云规定变量中不能传链接、网址，`${name}` 存在因域名被判定为链接而审核失败或发送被拦截的风险，请以审核结果为准。
2. 在 RAM 控制台创建一个只授予 `dysms:SendSms` 权限的 RAM 用户，生成 AccessKey。不要使用主账号 AccessKey。

### 配置

在「系统设置 → 基本设置 → 域名通知 → 阿里云短信」填写 AccessKey ID、AccessKey Secret、签名名称、模板 Code 和接收手机号（输入一个号码按回车添加，点号码上的 × 移除；粘贴多行或逗号分隔的列表会自动拆开，最多 1000 个），点「保存域名通知」。五项需同时填写；全部清空后保存即关闭短信。

- AccessKey Secret 保存后不会再返回给页面，留空保存表示保持原值；清空 AccessKey ID 会一并清除 Secret。
- 「测试短信通知」会向全部已保存号码发送一条真实短信（产生费用），`${name}` 为 `example.com`，`${status}` 为「测试」。「阿里云已受理」只表示接口调用成功，是否送达以手机实际收到为准。
- 在「域名监控」为需要的域名打开「短信通知」，桌面端可跨页勾选后批量设置。

### 发送规则

| 事件 | 是否发短信 | `${status}` |
| --- | --- | --- |
| 严重异常 | 是 | 严重 |
| 警告提醒 | 是 | 警告 |
| 到期提醒 | 是 | 即将到期 / 今天到期 / 已到期 |
| 恢复正常 | 否（模板是故障通知，恢复仍走钉钉） | — |

- `${name}` 为域名，域名里的点会换成下划线（如 `cpolar_top`）：阿里云会把 `cpolar.top` 这样的域名当作链接拒发（`isv.PARAM_NOT_SUPPORT_URL`），而「·」这类非常用符号又会被判为不支持的内容（`isv.UNSUPPORTED_CONTENT`）；`${time}` 为发现时间（`YYYY-MM-DD HH:mm:ss`），`${msg}` 只包含异常的检查项名称（如「权威 DNS 解析异常、公共 DNS 解析异常」）或到期说明。探测明细中的 NS 主机名和 IP 不会进入短信变量，完整明细在钉钉和「告警记录」查看。每个变量截断到 35 个字符以内。
- 持续故障按域名的提醒间隔重复发送。阿里云对同一签名、模板、手机号限制每天 50 条通知短信。
- 连接失败、限流和阿里云服务端错误会退避重试，最多 5 次。签名、模板、号码、AccessKey 等配置错误不重试，在「告警记录」的短信状态提示中查看错误码。接口响应超时时短信可能已发出，为避免重复发送也不自动重试。
- 域名恢复后，尚未发出的故障短信自动取消；关闭某个域名的短信或停用监控，会取消其排队中的短信。

通知生效需要运行一个启用调度器的应用实例，并能出站访问权威 DNS 的 UDP/TCP 53 端口，以及注册局、公共 DNS、钉钉 Webhook 和 `dysmsapi.aliyuncs.com` 的 HTTPS 接口。导入本地测试数据时，先移除生产通知配置（钉钉地址与短信 AccessKey），仅设置测试用的配置。可使用环境变量 DISABLE_HOST_MONITOR=true 暂停本地主机的定时 Ping，同时保留域名探测；DISABLE_NOTIFICATIONS=true 会关闭全部外部通知，包括短信；如需在这样的环境里手动点「测试钉钉通知 / 测试短信通知」，再设置 ALLOW_TEST_NOTIFICATIONS=true，自动告警仍然不会发出。

要覆盖监控服务自身掉线，建议另设不同网络的 HTTPS 检查，访问一个专门用于测试的隧道接口。注册商及 DNS 服务的操作审计可独立订阅，帮助更早发现误删或未授权变更。
